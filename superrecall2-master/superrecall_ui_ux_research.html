SuperRecall UI/UX research report: dark mode colour system, typography, card patterns, micro-interactions, navigation, and session flow recommendations.

Context

SuperRecall targets working professionals studying for certifications in 5–10 minute commute bursts. Sessions happen in low-light environments (trains, evening desks). Dark mode is not optional — it is the primary use environment. The following recommendations are grounded in that reality.

1 · Dark mode colour system

Background layer stack

Avoid pure #000000 — it causes OLED halo on high-contrast text. Use near-blacks with a slight warm or cool tint to establish depth without harshness. Page → sheet → card → elevated card: each surface is ~6–8 pts lighter.

Accent palette (dark-optimised)

Primary
Success
XP
Danger

On dark surfaces, saturated brand colours pop without boosting brightness. Desaturate each colour by ~15% from its light-mode value. Never put two saturated accents side by side — use one anchor, rest in grey.

Text contrast

Heading#F0EFF8 — 4.8:1
Body#C8C6D8 — 3.9:1
Muted#8A8899 — 2.5:1

Avoid pure white #FFFFFF — causes halation. Off-white with a slight purple hue matches the dark background tint and reduces eye strain in dark spaces.

Semantic token names

surface-base#0D0D0F
surface-card#1E1E24
surface-elevated#26262D
border-subtlergba(255,255,255,.07)

Token naming matters — name by role, not value. Flutter ThemeExtension can hold these as constants next to their light equivalents.

Elevation via brightness

In dark mode, depth is conveyed by lightening surfaces, not adding box-shadows (shadows disappear on dark bgs). Each elevation level is +6 lightness points. Cards = 3dp, modals = 8dp, tooltips = 12dp. Avoid blur/glassmorphism — it is expensive in Flutter and flickers on mid-range Android.

2 · Typography for cognitive load

Use a single humanist sans (Inter or the device system font). Two weights only: 400 for body, 500 for headings. Line height 1.7 on answer text — the user is reading while processing, not skimming. Minimum body size 16px; answer text should never drop below this even in compact layouts.

Rating state: 4-button strip at the bottom, full-width. Labels are text + colour coded — red → amber → green → purple. This matches SM-2 quality scores 1–4. Avoid using emoji as the sole indicator.

Card interaction principles

Tap-to-flip, not scroll-to-reveal

The entire card surface is the tap target. Do not use a "Show answer" button buried at the bottom — one hand, one thumb, commute context.

Swipe semantics

Left = skip/again, Right = easy, Up = AI explanation. These map to existing muscle memory from dating and content apps. Show a translucent hint label on first-use only.

Session time estimate upfront

"~6 min · 12 cards" shown before starting. Professionals need to know if they can finish a session before their stop. If a session will be interrupted, auto-save and resume is mandatory.

AI explanation as a layer, not a screen

The Gemini explanation should slide up as a bottom sheet over the card, not navigate to a new screen. The card remains visible at the top so the user keeps context. Dismiss with swipe-down.

4 · Micro-interactions & feedback loops

Streak & XP surface

+20 XP 7-day streak

Show XP and streak as transient chips on card completion — fade in at the top of the card, auto-dismiss after 2s. Never block the next card with a full-screen celebration. Research shows "inchstone" feedback (small frequent wins) increases session completion more than milestone-only celebrations.

Progress ring on home

8 of 12 done today

~4 min to finish

Single-ring progress on the home screen replaces the current card-count list. Animates on enter (0→65%). Much more readable at a glance during commute than a table of numbers.

Interaction feedback map

Card marked "Good" or "Easy"

Subtle green border flash (120ms) + haptic medium impact. No sound — public transport. XP chip fades in at top. Card slides left off screen.

Card marked "Again"

Subtle red border flash (80ms) + haptic light. No animation beyond colour — shame mechanics in learning apps correlate with session abandonment.

Session complete

Confetti particle burst (Lottie, under 30 frames) + summary card: cards reviewed, time taken, XP earned. One CTA: "Done" — not "Keep going" (avoid infinite scroll pressure on learning apps).

Streak milestone (7, 30, 100 days)

Full-screen moment (modal, not navigation) on first open after milestone. Dismiss with tap anywhere. Never show this mid-session — interrupts flow state.

Study is always tab 1 — the app's primary action. Curriculum (lesson browser) is second. Analytics is third — useful, not urgent. Settings is last. The current "Home → Lesson → Study" three-deep navigation adds friction for commuters. Primary action should be one tap from launch.

Session entry flow

App launch
↓
Home: ring + "Start session" CTA
↓
~6 min · 12 cards preview

First card shown

Max 3 taps from cold launch to first card. The current app requires ≥4. Each extra tap causes ~8% session-start drop-off on commuter apps.

Skeleton loading states

Use skeleton screens instead of spinners everywhere. On a commute, a spinner triggers impatience; a skeleton signals "content is loading, keep reading the shape of what's coming." Animate with a slow shimmer (1.5s) only if OLED-safe.

6 · Commute-specific UX requirements

Thumb zone optimisation

All primary interactions (flip, rate, advance) must be reachable with one thumb in the bottom 55% of the screen. Keep the top area for passive info only (topic label, progress). Minimum tap target: 48×48 dp.

Interruption resilience

Auto-save state on every card rating, not on session end. If the app is killed mid-session, resume from the exact card. Show "Resume session" prominently on next launch. Do not restart the session counter.

Offline-first session start

Sessions must start offline — subway tunnels kill connectivity. Pre-fetch the next session's cards on app open over WiFi/LTE. The SRS data is already local in Isar, but AI explanation fetches need a graceful offline fallback message.

7 · What the competition gets wrong (opportunity gaps)

Anki — powerful, visually dated

Users explicitly call it "not modern-looking" and "confusing to navigate." The card creation friction is high enough that people abandon before seeing the SRS benefit. SuperRecall's curated content removes this barrier — lean into that with UI that signals "just press start."

Duolingo — gamification over retention

Streak mechanics are aggressive to the point of anxiety. Users report the fear of losing a streak outweighs learning motivation. SuperRecall should show streaks as celebration, not obligation — and never use loss-aversion language ("Don't lose your streak!").

8 · Flutter implementation notes

Use ThemeExtension for the full colour token set

Define semantic tokens (surfaceBase, surfaceCard, textPrimary, accentPrimary…) as a ThemeExtension — not scattered ColorScheme overrides. This makes light/dark switching a single Theme.of(context).extension<AppColors>() call per widget.

Use Lottie for completion animations, not CustomPainter

Confetti and celebration frames in Lottie are far cheaper than CustomPainter particle systems on mid-range Android. Keep Lottie files under 30KB — the lottie_flutter package streams them from assets without blocking.

Card flip: AnimatedCard with PageView, not Navigator

Use PageView with a custom TweenAnimationBuilder for the card flip animation. Navigator.push for each card creates a deep stack that breaks the swipe-back gesture on iOS and tanks memory on longer sessions.

Honour system dark mode by default

Set the app's initial theme to MediaQuery.platformBrightness — respect the system preference without asking. The settings toggle is for override, not default. Users who want light mode will find it; users who set their phone to dark mode at midnight will not be blinded.
