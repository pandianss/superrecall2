🔴 Critical — ships broken or insecure
Bug
Provider declaration order crash. In app.dart, SrsController and EngagementController are declared via ChangeNotifierProxyProvider2<StorageService, SyncService, …> at the top of the list, but SyncService isn't registered as a Provider until near the bottom. MultiProvider builds in order — this crashes with a "could not find the correct Provider" error at startup on every platform.
Security
Real Firebase API key committed to source. firebase_options.dart contains a live apiKey, appId, messagingSenderId, and projectId. Anyone with access to the repo can write to or read from the Firestore collection unless Firestore security rules are locked down. Rotate the key and move secrets to environment injection or gitignored files.
Bug
Firebase not configured for Android or iOS. DefaultFirebaseOptions.currentPlatform throws UnsupportedError for every native platform. The app is built for mobile-first learners, yet it literally cannot initialise Firebase on Android or iOS. The FlutterFire CLI was only run for web.
Data loss
Sign-out destroys all local data. SyncService.signOut() calls _storage.clearAll() before re-signing-in anonymously. An anonymous user who accidentally taps "sign out" loses every lesson and SRS interval permanently, with no confirmation dialog and no way to recover.
🟡 Warnings — correctness and design issues
Serialisation
Save/load format mismatch for monthsToGoal. ProgressController._save() writes monthsToGoal into the progress blob, but StorageService.saveProgress() only persists completedLessons and quizAttempts. The goal setting is silently dropped on every restart.
Design
LearningSessionController is a plain ProxyProvider, not a ChangeNotifierProxyProvider. It cannot call notifyListeners(), so any widget watching the session queue will never rebuild when the queue changes. This likely makes the daily session screen appear stale after completing items.
UX risk
AI features require users to supply a Gemini API key. The bring-your-own-key model is a significant friction point for the target audience (working professionals, not developers). Most users will never reach the AI explanation or quiz generation features. Consider a free-tier quota or a shared backend key.
SRS
Ease-factor ceiling caps learning acceleration. The ease factor is clamped at 2.5 (the SM-2 default) rather than, say, 3.0. Users who perform well consistently never see their intervals grow faster than average, which undercuts the "adaptive" promise.
Sync
No merge strategy on cloud pull. pullRemoteProgress() overwrites local state with whatever Firestore returns. If a user studies offline and then connects, their offline progress is silently replaced rather than merged. A timestamp-based last-write-wins or union merge is needed.
Docs
README references stale file paths. lib/screens/home_page.dart, lib/models/learning_models.dart are cited but the real paths are under lib/features/study/…. A new contributor following the README will be confused immediately.
🟢 What's solid
Architecture
Clean feature-based folder structure. Splitting by study / ai / engagement with sub-layers (domain, presentation, state) is well-suited for this scale and makes future contributors productive quickly.
Reliability
Debounced sync and upsert-mode writes are well-thought-out. The 3-second debounce on pushLocalProgress() and the avoidance of clear() before Isar writes both prevent data loss on crash or rapid input.
Testability
clock package enables deterministic SRS tests. Using withClock(Clock.fixed(…)) in tests means SRS scheduling is fully reproducible — the right call for an algorithm where timing is the core logic.
Security
Gemini key stored in flutter_secure_storage. Even though the UX is friction-heavy, the key at least never hits disk in plaintext. Good practice for credentials that users do supply.
